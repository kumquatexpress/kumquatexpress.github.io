# Design principles and iteration loop

Scope: Boyang's personal website. These principles reflect his judgments of versions 1 and 2; exact visual solutions remain hypotheses.

1. **Character with restraint.** Retain an authored, playful sensibility while avoiding competing attention demands. Neither a professional editorial résumé nor a wall of colorful artwork has satisfied the brief.
2. **Compose before decorating.** Make relationships of scale, placement, and negative space intentional. A conventional section stack does not become creative through more stickers, labels, or images.
3. **Make language earn its place.** Keep identity, real project context, useful navigation, and actionable instructions. Remove redundant invitations, narration, and visible process/provenance commentary. Put production documentation in the repository.
4. **Give imagery a hierarchy.** Image count, specific assets, palette, and hero size are open questions. Test whether images compete, repeat, or support a clear focal point rather than treating more imagery as better.
5. **Preserve function and truth.** Keep factual attribution, keyboard/touch access, reduced motion, responsive layout, and smooth loading. These are pass/fail constraints, not points to average against aesthetic appeal.

## One loop

- Freeze a specific baseline commit and capture desktop/phone at fixed viewport and state.
- Record a single change hypothesis, allowed scope, and acceptance rule before editing.
- Implement one candidate on a branch. Keep unrelated assets, features, and styling fixed. Deleting text can still affect rendered composition; record that rather than claiming every other variable is fixed.
- Collect independent role-based critiques before discussion. For paired review, use neutral A/B names and shuffled order, the same exact user feedback, equal capture settings, full-page and first-viewport views.
- Ask each judge for A/B/unclear, concrete improvement, regression/unresolved issue, and whether neither sufficiently addresses the overall feedback. Keep raw findings and dissent. No weighted score or claim that model votes establish user preference.
- Select a candidate for user review only if at least two judges prefer it for the predeclared target, can identify visible evidence, and no functional/factual regression remains. An unclear outcome retains the baseline.
- Show the user the bounded before/after. Their response decides acceptance; it selects the next experiment. No automatic chain of broad redesigns.

Different roles supply different criteria, not independent human taste. Shared model biases and recognition of earlier versions limit blinding. Technical test passes establish working behavior, not aesthetic success.

## User evidence

- V1: too textual/professional/clean; wanted color, 3D/gaming/video/art, and character.
- V2: overshot into chaos and too many images; composition still felt like a boring table of contents; too much text/captioning/labels/disclaiming.
- Process request: targeted iterative changes, critique rounds with diverse judging, hill climbing against principles.
